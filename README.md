# 留学跟进顾问

面向留学咨询销售的跟进助手。客户沉默或改口之后，继续对话时只使用仍然有效的事实。遇到价格、事实冲突，或政策文档里没有依据，就停止自动回答，转给人工。

客户、对话和政策都是合成数据，用来把记忆、检索和转人工放在同一条任务里验证。

## 问题

销售同时跟进很多客户。预算、意向国家和已经答应过的事如果只留在长对话里，下一轮容易沿用旧事实。价格和政策又不能靠模型现编。

这个项目要验证的是：跟进前先召回这个客户的有效事实；事实互相冲突，或文档没有依据时，动作改为转人工，而不是继续生成可发送回复。

## 方案

系统提示词里只放人设和禁令。客户事实放在长期记忆里，每条带来源、时间和是否经客户明确说过。政策放在短文档里，回答前做匹配。

跟进时可以使用四件事：

| 工具 | 作用 | 边界 |
|---|---|---|
| 查档案 | 读取该客户已经确认的事实 | 只读 |
| 查政策 | 在短文档中匹配依据 | 只读；没有匹配结果就说明没有依据 |
| 写下一次跟进 | 留下一条跟进草稿 | 只保存在本地，不发送 |
| 转人工 | 在价格、冲突或缺少依据时停止自动回答 | 只做本地标记 |

记忆有三种行为：写入客户明确说过的事实，按客户召回，以及在新旧值不同时保留两条并标成冲突。预算从 30 万改成 15 万，是冲突的例子。

## 评测

同一套合成对话会跑两个版本。一版把全部历史放进提示词，一版只注入召回到的事实和匹配到的政策。用例覆盖记混、忘掉、人设漂移、编造价格或政策、该转人工没有转、知识库没有命中仍给出判断。结果按类别统计，并单独复核预算改口这一条。样本用于说明设计是否成立，不代表线上效果。

范围、记忆字段和转人工条件见 [docs/scope.md](docs/scope.md)。
